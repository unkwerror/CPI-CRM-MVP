### Восстановление даты отправки

Импортёр не читает дату материала из строки, поэтому автор legacy-версии остаётся
в `ACTIVATED + UNKNOWN` навсегда: активация доказана, судить о свежести нечем.
Задача `legacy-artifact-dating` (`pnpm --filter @cpi-crm/importer
legacy-artifact-dating [-- --apply]`) достаёт дату из сохранённой исходной строки
по столбцам вида «Отметка времени» или «Время создания» и, если в строке даты нет,
из даты в названии мероприятия с точностью до месяца. Без `--apply` печатает план.

Правила, которые задача не нарушает:

- Дата позже момента записи факта в систему или раньше 2010 года не берётся —
  строка остаётся недатированной.
- Если в строке несколько дат и ни одна не названа датой отправки, задача не
  угадывает; версия остаётся недатированной.
- Заполняется только пустая дата: триггер `cpi_guard_artifact_version_immutability`
  разрешает это один раз и только вместе с причиной, известная дата неизменяема.
- Каждая простановка попадает в `audit_log` как `artifact_version.legacy_dated`
  с источником даты; после простановки статусы авторов пересчитываются.

## Защитные решения

- Формулы не исполняются, cached formula result не используется как доверенное значение.
- СНИЛС и дата рождения редактируются до raw staging: сохраняются координаты,
  заголовок и hash строки, но не исходное значение.
- Наблюдение без отдельных фамилии, имени и отчества русскими буквами получает
  `REJECTED`; полностью непригодная строка — `IGNORED`. Исходная строка не удаляется,
  но участник и его операционные связи не создаются.
- Telegram user ID является главным идентификатором. `AUTO_DEDUPE_V2` также объединяет
  одинаковое строгое русское ФИО при отсутствии конфликта стабильных ID; остальные
  пары — только совместимые нормализованные имена при наличии чистого общего
  контакта и отсутствии конфликта external ID в одном namespace.
- Неоднозначные совпадения закрываются как `DISMISSED`, явные конфликты — как
  `NOT_DUPLICATE`; merge выполняется транзакционно, журналируется и обратим.
- Полный набор неотредактированных source fields доступен только ролям с
  `imports.read_raw`; bulk CSV — только ролям с `exports.bulk`.

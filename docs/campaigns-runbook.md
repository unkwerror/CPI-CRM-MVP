# Как запустить рассылку активации базы

Порядок работ для первой волны: приветственное письмо от стартап-студии с
приглашением на конкурс, сбор откликов и чистка тех, кто отпишется.

## Что нужно понимать про каналы

**Telegram достаёт не всех.** Бот может написать только тому, кто сам нажал
`/start`: у остальных в базе есть только `@username`, и по нему отправить
нельзя. Сколько людей реально достижимо каждым каналом — на странице
«Достижимость базы» (`/audience`).

**Email идёт через свой ящик в Яндекс 360, и это жёсткий потолок.** По SMTP
Яндекс пропускает **300 писем в сутки с ящика**, и превышение не просто
отбивается: отправка блокируется на 24 часа, а каждая новая попытка в это время
продлевает блокировку ещё на сутки. Воркер считает отправленное за последние 24
часа сам и останавливается заранее, но планировать волны нужно из тех же 300.
Базу в 3000 адресов это растягивает на десять дней — либо берите отдельный
сервис рассылок, когда объёмы вырастут.

**Отписка не удаляет человека.** Она пишется в `consent_records` как отзыв
согласия, и все следующие аудитории её учитывают автоматически. Из реестра
участник никуда не девается: история артефактов и мероприятий остаётся.

## Что подключить на стороне Яндекса

1. **Платный тариф Яндекс 360 для организации.** С лета 2026 доменная почта без
   тарифа не работает по SMTP вообще — только веб и мобильное приложение.
2. **Домен в Яндекс 360** с подтверждением владения и записями в DNS: MX, SPF
   (`v=spf1 redirect=_spf.yandex.net`), DKIM из панели и DMARC. Без DKIM и DMARC
   массовое письмо уедет в спам почти гарантированно.
3. **Отдельный ящик для рассылок**, например `news@домен`. Отдельный — потому
   что суточный лимит считается на ящик, и упереться в него рабочей перепиской
   было бы обидно.
4. **Пароль приложения** для этого ящика (Яндекс ID → Безопасность → Пароли
   приложений → Почта). При включённой двухфакторной аутентификации обычный
   пароль по SMTP не примут; в `SMTP_PASSWORD` кладётся именно он.
5. **Ящик, куда падают отчёты о недоставке.** Своего SMTP никто не уведомляет о
   бounce-ах: письма «Delivery Status Notification» приходят обратно на адрес
   отправителя, и адреса из них нужно чистить руками.

## Настройка окружения

Пустой `SMTP_HOST` или `TELEGRAM_BOT_TOKEN` выключает свой канал целиком,
воркер при этом работает как обычно.

| Переменная | Зачем |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Отправка в бот. Тот же токен, что у CPI-TG-BOT. |
| `CAMPAIGN_BOT_LINK` | Ссылка на бота: на неё ведут кнопки отклика в письме. |
| `SMTP_HOST` / `SMTP_PORT` | `smtp.yandex.ru` и `465` (SSL). |
| `SMTP_USER` / `SMTP_PASSWORD` | Полный адрес ящика и пароль приложения. |
| `SMTP_DAILY_LIMIT` | Потолок отправки за сутки, по умолчанию 300. |
| `CAMPAIGN_FROM_EMAIL` | Адрес в поле «От кого». Должен совпадать с `SMTP_USER` или быть его алиасом, иначе Яндекс подменит его сам. |
| `CAMPAIGN_FROM_NAME` | Имя отправителя. |
| `CAMPAIGN_REPLY_TO` | Куда попадут ответы живых людей — лучше на читаемый ящик, а не на `news@`. |
| `CAMPAIGN_PUBLIC_URL` | Внешний адрес API, например `https://crm.62-113-105-225.sslip.io/api`. На него ведут пиксель открытия и ссылка отписки. |
| `CAMPAIGN_LINK_SECRET` | Секрет подписи этих ссылок. Одинаковый у API и воркера, генерится `openssl rand -hex 32`. |
| `CAMPAIGN_BATCH_SIZE` | Сколько сообщений воркер берёт за проход, по умолчанию 100. |

В боте нужны `CRM_API_URL` и `CRM_INTEGRATION_TOKEN` — по ним он возвращает в
CRM нажатия кнопок и переходы из письма.

## Отписка и открытия

Провайдерских статусов у своего SMTP нет, поэтому обратная связь встроена в
само письмо:

- **Пиксель открытия** — `GET /public/campaigns/pixel/<токен>`, одно открытие на
  получателя. Цифра всегда занижена: часть клиентов не грузит картинки.
- **Ссылка отписки** — `/public/campaigns/unsubscribe/<токен>` плюс заголовки
  `List-Unsubscribe` и `List-Unsubscribe-Post`, чтобы кнопка отписки появилась
  в самом почтовом клиенте. По ссылке открывается страница с подтверждением:
  почтовые антивирусы ходят по ссылкам сами, и отписывать по одному переходу
  нельзя.

Токен в ссылке подписан `CAMPAIGN_LINK_SECRET` и привязан к цели, так что по
чужому адресу нельзя ни отписать соседа, ни накрутить открытия. Отписка пишется
в `consent_records` как отзыв согласия и учитывается во всех будущих аудиториях.

## Порядок отправки

1. **Черновик** (`/campaigns`, «Новая рассылка»). Текст правится только здесь:
   после утверждения он замораживается, иначе половина базы получит одну
   версию, а половина — другую, и сравнивать отклик будет не с чем.
2. **Проверить аудиторию.** На странице рассылки видно размер аудитории и пять
   примеров с подстановками. Отписавшиеся и недостижимые уже исключены.
3. **Тест на себе.** Заведите себя участником с рабочим адресом и отправьте
   волну на сегменте из одного человека.
4. **Утвердить** — отдельное право `campaigns.send`, отдельная кнопка.
5. **Отправлять волнами.** Каждая волна фиксирует список получателей на момент
   запуска; повторно один человек в кампанию не попадёт. Для почты волна не
   должна превышать суточный лимит: начните со 100 адресов, посмотрите открытия
   и отписки, следующие дни — по 200–300.
6. **Пауза** снимает с очереди всё неотправленное сразу.

## После волны

Отклики видно в карточке рассылки: интересен конкурс, просят подробности,
отписались, а для писем ещё сколько человек открыло. Отписавшиеся уже
исключены из будущих аудиторий — руками ничего делать не нужно. Полное удаление
из базы (`/participants/:id`, «Удалить») нужно только по требованию самого
человека: оно необратимо и оставляет лишь хеши контактов, чтобы участник не
завёлся заново следующим импортом.

## Что делать с недостижимыми в Telegram

Это и есть смысл ссылок в письме: кнопки отклика ведут в бота с payload
`cmp_<id>_<действие>`. Человек отвечает на письмо одним нажатием — и попадает в
Telegram, откуда его дальше можно достать бесплатно и без email-согласия.
Поэтому в первой email-волне кнопка отклика важнее ссылки на лендинг.
